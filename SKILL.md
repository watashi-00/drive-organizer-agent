# Google Drive Organizer Agent Skill

Use this skill when organizing a user's Google Drive with the local `drive-organizer` CLI.

## Purpose

Help a user organize Drive files by reading exported Drive inventories, creating folders, and moving Drive items through explicit commands.

## Critical Safety Rules

- Never assume file names are unique. Use `id` fields from the inventory.
- Prefer a written organization plan before executing changes.
- Use `--dry-run` for risky or broad move batches.
- Do not request, print, or modify `credentials.json` or `token.json`.
- Do not delete Drive files in this MVP. This project supports listing, folder creation, and moving only.
- When uncertain about a destination, stop and ask the user.

## Expected Files

- `README.md`: user setup and command guide.
- `drive-inventory.json`: current Drive inventory generated by `drive-organizer list`.
- `drive-inventory-after.json`: optional verification inventory after changes.
- `credentials.json`: required Google OAuth client file, local only.
- `token.json`: generated OAuth token, local only.

## OAuth Setup Checks

If the user sees an "Access blocked" or "app has not completed verification" message, instruct them to keep the OAuth app in testing mode, add their Google account as a test user, and add this exact scope URL in the OAuth consent screen:

```text
https://www.googleapis.com/auth/drive
```

If the Google Cloud Console scope picker does not show the Drive scope by search, tell the user to paste the full URL directly.

## Recommended Agent Workflow

1. Confirm that the user has configured `credentials.json`.
2. Generate or ask for a fresh inventory:

```bash
drive-organizer list --output drive-inventory.json
```

3. Inspect the inventory JSON.
4. Group items by practical categories such as documents, finances, work, media, archives, or project names.
5. Produce a proposed plan with:
   - folders to create,
   - files or folders to move,
   - exact source item IDs,
   - exact destination folder IDs or newly created folder names.
6. Ask the user to approve the plan if it is broad or ambiguous.
7. Execute commands explicitly.
8. Export a new inventory and compare the relevant items.

## Commands

List Drive items:

```bash
drive-organizer list --output drive-inventory.json
```

List with a Drive query:

```bash
drive-organizer list --query "'FOLDER_ID' in parents" --output folder-items.json
```

Create a folder at Drive root:

```bash
drive-organizer mkdir "Folder Name"
```

Create a subfolder:

```bash
drive-organizer mkdir "Subfolder Name" --parent PARENT_FOLDER_ID
```

Preview a move:

```bash
drive-organizer move ITEM_ID DESTINATION_FOLDER_ID --dry-run
```

Move an item:

```bash
drive-organizer move ITEM_ID DESTINATION_FOLDER_ID
```

## Planning Guidelines

- Keep folder names short, stable, and human-readable.
- Avoid over-nesting. Two or three levels are usually enough.
- Preserve existing meaningful folders unless the user asks for a full reorganization.
- Treat shared folders carefully; moving shared items may affect collaborators.
- For duplicate-looking names, compare `id`, `parents`, `mimeType`, and `modifiedTime`.

## Output Expectations

When reporting work to the user, include:

- created folder names and IDs,
- moved item names and IDs,
- any skipped ambiguous items,
- verification command results or a note if verification was not run.
